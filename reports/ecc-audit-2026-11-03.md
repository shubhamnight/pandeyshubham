## Perimeter and reconstructed contracts

Three bounded slices: media request/preview lifecycle (`mobile-media.js`,
`hobby-media-runtime.js` and callers); overlay keyboard interaction (Travel and
Music components/styles); delivery and regression coverage (existing runner,
manifest, editor UI and backend isolation). Existing source checks, browser
journeys, media-quality comparisons and backend stress remain the correctness
gate. No framework replacement, project/resume content invention or canceled
impact-animation work is included.

- Optional mobile metadata must never block mounting or replace displayed media.
  Pending requests must deduplicate, expire and permit recovery.
- A failed preview decode must retain successful media, keep its selected item
  for retry and reject obsolete asynchronous results. Hidden/modal-covered
  videos stay paused; departure cancels work.
- Keyboard-selectable Travel media must expose action semantics and visible
  focus. Escape from the Songs disclosure must return focus to its trigger
  while retaining the surrounding dialog.
- Crop editor checks must use isolated synthetic media. No test may upload,
  delete or change the owner's real media, locations or state.

These contracts extend the [historical bug matrix](../checks/README.md). That
matrix covers prior loading, hero, Skills, Hobbies, overlays, cursor, offline,
responsive typography, media, browser-engine and backend failures. Source-module
checks apply to shared code; viewport emulation is distinct from physical-device
evidence. Some historical problems are represented by preservation assertions;
only the explicitly documented negative controls restore old faulty behavior.

## Initial performance evidence

Before production edits, separate fresh Chromium contexts loaded hosted and local
production output at laptop 1366×768, phone 393×873 and tablet 820×1180. Touch
profiles used DPR 3 and 4× CPU slowdown; laptop used DPR 1 and no slowdown. Data:
`output/ecc-audit-2026-11-03/*-baseline.json`. This is a controlled diagnostic,
not physical display FPS or field INP. Navigation was triggered through the
existing navigation handler; native input is exercised separately by the
regression journeys.

No page errors or HTTP 4xx/5xx appeared in these six normal journeys. Larger
stalls occur during initial loading/preparation. A hosted laptop 180 ms task
was attributed to the model build callback; every builder creates its renderer
before its first yield. `new WebGLRenderer` and first drawing-buffer work are
synchronous driver calls. Phone preparation also includes shader compilation
and first-use render uploads. Existing preparation yields between draws. Extra
yields elsewhere cannot split a single driver call, so no unmeasured scheduling
change is promoted as a fix. These measurements do not resolve every reported
physical-device stutter or the older partial-hero capture uncertainty.

### Complete run and Firefox diagnosis

`npm test -- --output=output/regressions/ecc-final-2026-11-03` completed with
**41/45 checks passing**, including the build. Failed cases were
`overlay-keyboard`, `preview-quality`, `browser-engines`, and
`historic-reproductions`. Original failures remain recorded; subsequent passes
must be attributed to their explicit reruns, not substituted into this result.

The last two failures shared a Windows Firefox test-window problem. With the
original launcher, instrumented native RAF callbacks arrived at roughly
1.2/3.3/7.4/15.5/31.9 seconds, while one-second timers continued. Both laptop and
fresh-phone contexts delivered only nine RAF callbacks in about 46 seconds;
the morph had advanced 150 ms. DOM visibility/focus were true and its suspend
flag false. Agent Desktop independently observed an unfocused native window,
offscreen accessibility controls, and a stale blank-tab window surface.

This matches [Mozilla's documented Windows occlusion throttling and automation
fix](https://bugzilla.mozilla.org/show_bug.cgi?id=1802473). A controlled variant
setting only `widget.windows.window_occlusion_tracking.enabled=false` passed
the three instrumented Firefox journeys: 262/279/279 morph frames, median
RAF gap about 6.06 ms, and morph completion in 1.68–1.77 seconds. The launch
helper now applies that preference solely to temporary headed Windows Firefox
profiles, preserving explicit caller overrides. No real Firefox profile,
operating-system setting, application animation clock or assertion was changed.
Raw evidence: `output/firefox-intro-diagnostic/` and
`output/firefox-intro-occlusion-pref/`. Standard regression acceptance is still
separate from this controlled diagnosis, and subsequently passed.
